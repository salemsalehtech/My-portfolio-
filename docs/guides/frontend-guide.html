1الصورة الكبيرة

الموقع عبارة عن تطبيق React واحد (Single Page Application) فيه جزئين:

  • الموقع العام على الرابط / — اللي الزوار بيشوفوه: Hero، About، الخدمات، المهارات، المشاريع، الآراء، يوتيوب، التواصل.
  • لوحة التحكم على الرابط /#/admin — اللي انت بس بتدخلها بالإيميل والباسورد وبتعدّل منها كل محتوى الموقع.

الواجهة نفسها ملفات ثابتة (HTML + CSS + JavaScript) متنشورة على GitHub Pages. أما البيانات (المشاريع، المهارات، الآراء…) فمش جوه الكود — بتيجي من السيرفر (API) على Render، واللي بيقرا ويكتب في قاعدة البيانات MongoDB Atlas.

القاعدة الأهم في المشروعأي محتوى بيظهر للزائر لازم يتعدّل من لوحة التحكم — مش من الكود. عشان كده كل قسم بيجيب بياناته من الـ API، ولو مفيش بيانات بيرجع لقيم افتراضية أو بيختفي.

2تشغيل المشروع على جهازك

المشروع جزئين بيشتغلوا مع بعض، فمحتاج اتنين Terminal:

# Terminal 1 — السيرفر (لازم MongoDB يكون شغّال على جهازك)
cd "D:\Work\Web applications\My-portfolio-\My-portfolio-\server"
npm install      # أول مرة بس
npm run dev      # API on http://localhost:4000

# Terminal 2 — الواجهة
cd "D:\Work\Web applications\My-portfolio-\My-portfolio-\client"
npm install      # أول مرة بس
npm run dev      # افتح http://localhost:5173

وقت التطوير، أي طلب من الواجهة لـ /api/... بيتحوّل تلقائيًا للسيرفر على بورت 4000 — ده إعداد اسمه proxy موجود في client/vite.config.js. وفي النسخة المنشورة، الواجهة بتكلم السيرفر على Render من خلال الرابط المكتوب في client/.env.production.

نصيحةلو شغّلت السيرفر وطلع خطأ EADDRINUSE :::4000 يبقى فيه نسخة تانية من السيرفر شغّالة على نفس البورت — اقفلها الأول.

4مفاهيم React من كودك

1) المكوّن (Component) و JSX

المكوّن = دالة بترجع شكل جزء من الصفحة. الشكل ده مكتوب بـ JSX — شبه HTML جوه JavaScript. مثال حقيقي مبسّط من Footer.jsx:

client/src/components/Footer.jsx 
export default function Footer({ settings }) {
  const { t, lang } = useSite();
  return (
    <footer>
      <div className="footer-name">{pick(lang, settings.nameEn, settings.nameAr)}</div>
      <div className="footer-copy">{t.footer.rights}</div>
    </footer>
  );
}

لاحظ: className بدل class، وأي قيمة JavaScript بتتحط بين { }.

2) الـ Props — بيانات داخلة للمكوّن

الـ props هي "المعطيات" اللي المكوّن الأب بيبعتها للابن. في Portfolio.jsx بنجيب إعدادات الموقع مرة واحدة ونوزّعها:

<Hero settings={settings} />
<Contact settings={settings} />
<Footer settings={settings} />

3) الـ State — بيانات بتتغير وبتعيد الرسم

useState بيحفظ قيمة جوه المكوّن، ولما تتغير React يعيد رسم المكوّن. مثال من فورم التواصل:

client/src/components/Contact.jsx 
const [status, setStatus] = useState("idle"); // idle | sending | success | error
// ...
setStatus("sending");
await api.post("/contact", formData);
setStatus("success");   // الشاشة تتحدّث لوحدها وتظهر رسالة النجاح

4) الـ Effect — حاجة تحصل بعد الرسم

useEffect للحاجات اللي "برّه" الرسم: طلب بيانات من السيرفر، تايمر، الاستماع للـ scroll. مثال: تبديل المسميات في الـ Hero كل 3.2 ثانية:

useEffect(() => {
  if (count < 2) return;                 // مفيش حاجة تتبدّل
  const cycle = setInterval(() => { /* المسمى اللي بعده */ }, 3200);
  return () => clearInterval(cycle);       // تنضيف لما المكوّن يختفي
}, [count]);                                 // يتعاد لو عدد المسميات اتغير

5) Custom Hook — منطق بتعيد استخدامه

لو نفس المنطق متكرر في أكتر من مكوّن، بنحطه في دالة اسمها يبدأ بـ use. أشهر مثال في المشروع useCollection: بيجيب قايمة من السيرفر ويرجّع { data, loading }:

const { data: projects } = useCollection("/projects");

6) Context — بيانات للموقع كله

بدل ما نبعت اللغة والثيم كـ props لكل مكوّن، SiteContext بيخزّنهم مرة واحدة فوق كل حاجة (في App.jsx)، وأي مكوّن يقدر يقراهم بـ:

const { t, lang, theme, toggleLang, toggleTheme } = useSite();

7) العرض المشروط والقوايم

// لو مفيش خدمات، القسم كله ما يترسمش
if (loading || items.length === 0) return null;

// قايمة: لازم key فريد لكل عنصر
{items.map((item) => <div className="service-card" key={item.id}>...</div>)}

5رحلة البيانات من الداشبورد للزائر

خلينا نتابع "إضافة خدمة جديدة" من أولها لآخرها:

  1. انت في الداشبورد (AdminServices.jsx) تضغط Save → api.post("/admin/services", ...).
  2. lib/api.js بيضيف التوكن بتاعك (Authorization: Bearer ...) ويبعت الطلب للسيرفر.
  3. السيرفر يتأكد إنك الأدمن، ويتحقق من البيانات، ويحفظها في MongoDB.
  4. زائر يفتح الموقع: Portfolio.jsx بينادي useCollection("/services") → طلب GET /api/services.
  5. القسم Services.jsx بياخد القايمة ويرسم الكروت.

lib/api.js — باب واحد لكل الطلبات

أي كلام مع السيرفر لازم يعدّي من api.get / post / put / patch / del — مش fetch مباشرة. الملف ده بيعمل 3 حاجات مرة واحدة: يحدد رابط السيرفر، يضيف التوكن لو انت مسجّل دخول، ويرمي خطأ واضح لو السيرفر رد بغلط.

الكاش — المحتوى يظهر فورًا للزائر الراجع

السيرفر المجاني على Render ممكن ينام، وأول طلب بعدها ياخد وقت. عشان كده lib/apiCache.js بيحفظ آخر رد في متصفح الزائر (localStorage). الزيارة الجاية: المحفوظ يظهر فورًا، وبعدين يتحدّث بالجديد من السيرفر.

1. فتح الموقععرض المحفوظ فورًا
←
2. طلب للسيرفرفي الخلفية
←
3. وصل الردتحديث الشاشة + حفظ نسخة جديدة

لوحة التحكم ما بتستخدمش الكاش — لازم تشوف البيانات الحقيقية دايمًا.

الثيم (فاتح / داكن)

  • الألوان كلها متغيرات في أول index.css: :root للداكن (رمادي غامق #141414) و:root.light للفاتح.
  • الافتراضي فاتح: <html class="light"> في index.html.
  • اختيار الزائر بيتحفظ في localStorage، وسكريبت صغير في index.html بيطبّقه قبل ما React يشتغل — عشان الصفحة ما "تومضش" بالثيم الغلط.

  • الأقسام الاختيارية (الخدمات، الشهادات، الآراء) بتختفي لو فاضية — وروابطها في الـ Navbar كمان. عشان كده Portfolio.jsx هو اللي بيجيب بياناتها ويديها للقسم وللـ Navbar.

  • فلتر المشاريع أزراره مش مكتوبة في الكود: بتتبني من حقل Tags في المشاريع نفسها، الأكتر استخدامًا الأول.
  • نافذة المشروع بتعرض "المشكلة ← الحل ← النتيجة" لو موجودين، وأزرار Demo/Code بتظهر بس لو الرابط حقيقي (يبدأ بـ http).
  • الصور والملفات في public/ لازم رابطها يتبني بـ import.meta.env.BASE_URL عشان الموقع شغّال تحت /My-portfolio-/.

8لوحة التحكم (Admin)

تسجيل الدخول خطوة بخطوة

  1. تفتح /#/admin/login وتكتب الإيميل والباسورد (AdminLogin.jsx).
  2. AdminContext.jsx يبعت POST /auth/login — ولو صح يرجع توكن (JWT) صالح 7 أيام.
  3. التوكن بيتحفظ في localStorage باسم adminToken — فالـ Refresh ما بيخرّجكش.
  4. api.js بيضيف التوكن لكل طلب، والسيرفر يرفض أي طلب أدمن من غيره.
  5. AdminLayout.jsx هو "الحارس": لو مفيش توكن يحوّلك لصفحة الدخول.

نمط صفحات الأدمن

أغلب الصفحات (Projects, Skills, Services, Testimonials, YouTube) نفس الشكل: جدول + نافذة فورم للإضافة والتعديل. الـ state المهم:

const [editing, setEditing] = useState(null); // null = مقفول | "new" = إضافة | id = تعديل
const [form, setForm] = useState(EMPTY);       // قيم الفورم الحالية
const load = () => api.get("/admin/services").then(setItems); // إعادة تحميل بعد أي تعديل

Analytics صفحة قراءة بس: أرقام ملخصة ورسم بياني SVG للزيارات اليومية (مع tooltip بالماوس والكيبورد وجدول بنفس الأرقام). البيانات بتوصل من lib/analytics.js في الموقع العام: زيارة واحدة لكل جلسة، ومش بيبعت حاجة لو انت مسجّل دخول كأدمن أو المتصفح طالب Do Not Track.

والصفحات اللي بتعدّل "مستند واحد كبير" (About و Profile & Links) بتستخدم مكوّنات مشتركة من pages/admin/FormParts.jsx: Field (حقل نص) وListEditor (قايمة بإضافة/حذف/ترتيب).

9الحركة عند النزول (useReveal)

العناصر اللي عليها data-ao بتبدأ شفافة (CSS: opacity: 0)، ولما توصل لها وانت نازل بتاخد class visible وتظهر بحركة.

const [headerRef, headerVisible] = useReveal();
<div ref={headerRef} className={`section-header ${headerVisible ? "visible" : ""}`} data-ao>

جوه useReveal بيستخدم IntersectionObserver — خاصية في المتصفح بتقول "العنصر ده بقى ظاهر في الشاشة".

درس اتعلمناهقبل كده كان useReveal بيراقب العنصر مرة واحدة وقت التحميل. فلو العنصر ظهر بعدين (مثلًا بعد ما البيانات وصلت) ما حدش كان بيراقبه، فيفضل شفاف للأبد — وده اللي خلّى قسم About "يختفي" مرة. الحل: ref بقى "callback ref" محفوظ في state، فأي عنصر يظهر في أي وقت بيتراقب.
تحذيرأي عنصر بتحط عليه data-ao لازم يكون معاه ref من useReveal ويتغيّر له class visible — وإلا هيفضل مخفي.

10إضافة ميزة جديدة

كل ميزة في الموقع بتتبني بنفس الخمس خطوات (قاعدة "كل حاجة من الداشبورد"). مثال: قسم "الشهادات":

  1. الموديل في السيرفر: server/src/lib/mongo.js (الحقول بنسختين En/Ar).
  2. API عام للقراءة: server/src/routes/certificates.js + سطر في app.js.
  3. API للأدمن (إضافة/تعديل/حذف): قسم جديد في routes/admin.js.
  4. صفحة أدمن: pages/admin/AdminCertificates.jsx (انسخ نمط AdminServices.jsx) + Route في App.jsx + رابط في AdminLayout.jsx.
  5. قسم العرض: components/Certificates.jsx + إضافته في Portfolio.jsx + العنوانين في translations.js + الستايل في index.css.
قبل ما تبدأاعمل branch جديد (git checkout -b feat/certificates). ولما تخلص: جرّب على جهازك → npm run build لازم ينجح → وبعدين انشر.

11النشر

بناء النسخة النهائية

cd client
npm run build     # يطلّع ملفات الموقع في client/dist

Vite بيقرا VITE_API_URL من .env.production ويحطه جوه الكود، وبيظبط كل الروابط على /My-portfolio-/ (من vite.config.js).

النشر على GitHub Pages — الطريقة الحالية

GitHub Actions متوقف حاليًا (مشكلة في الفوترة على الحساب)، فالموقع بيتنشر من branch اسمه gh-pages فيه محتوى dist/ بس:

npm run build
# انسخ محتوى client/dist لمجلد مؤقت فيه نسخة من branch gh-pages
# + ملف فاضي اسمه .nojekyll، وبعدين:
git add -A && git commit -m "deploy" && git push origin gh-pages

لما Actions يرجع يشتغل: Settings ← Pages ← Source = GitHub Actions، وساعتها أي push على main بينشر لوحده (.github/workflows/deploy-pages.yml).

بعد النشرافتح الموقع بـ Ctrl+Shift+R أو نافذة Incognito — المتصفح بيحتفظ بالنسخة القديمة حوالي 10 دقايق.

Stateبيانات جوه المكوّن، لما تتغير الشاشة تتحدّث.
Hookدالة React بتبدأ بـ use (useState, useEffect, useCollection...).
Effectكود بيشتغل بعد الرسم (طلبات، تايمرات).
Contextمخزن بيانات عام لكل الموقع من غير props.
Router / Routeاختيار الصفحة اللي تظهر حسب الرابط.
APIعنوان على السيرفر بتطلب منه أو تبعتله بيانات.
JWT / Token"تصريح دخول" موقّع بيثبت إنك الأدمن.
localStorageتخزين صغير جوه متصفح الزائر بيفضل بعد قفل الصفحة.
Buildتحويل الكود لملفات جاهزة للنشر (dist/).
RTLالكتابة من اليمين للشمال (العربي).
Cacheنسخة محفوظة من بيانات عشان تظهر أسرع.

الدليل ده بيوصف الكود في أكتوبر 2026. لو المشروع اتغيّر، الملف المصدر docs/guides/frontend-guide.html وتقدر تعدّله وتعيد طباعته بـ docs/guides/build-pdfs.sh.
