1الصورة الكبيرة

السيرفر برنامج Node.js مكتوب بـ Express، شغّال على Render. شغلته يستقبل طلبات من الواجهة، ويقرا أو يكتب في قاعدة البيانات MongoDB Atlas، ويرد بـ JSON. هو مش بيعرض صفحات — الصفحات كلها في الواجهة (React).

الواجهةبتطلب GET /api/projects
←
Express (app.js)helmet ← cors ← قراءة JSON ← الـ router
←
MongooseProject.find()
←
MongoDB Atlasبيرجّع المستندات

والرد بيرجع بنفس الطريق بالعكس: JSON فيه قايمة المشاريع.

الأدوات

الحزمةدورها

mongooseالتعامل مع MongoDB بـ schemas و models.

متغيرات البيئة

الإعدادات السرية أو اللي بتختلف بين جهازك والسيرفر الحقيقي ما بتتكتبش في الكود. على جهازك في server/.env (متجاهَل في git)، وعلى Render في صفحة Environment.

المتغيرمعناه

JWT_SECRETالسر اللي بيوقّع توكنات الدخول. إجباري ولازم يكون طويل وعشوائي.

لو MONGODB_URI أو JWT_SECRET ناقصين، server.js بيوقف فورًا برسالة واضحة — أحسن من سيرفر "شغّال نص شغل".

4أساسيات HTTP و REST

كل كلام بين الواجهة والسيرفر "طلب" (Request) و"رد" (Response). الطلب له method بيقول عايز تعمل إيه، وعنوان بيقول على إيه:

Methodمعناهمثال من المشروع
GETهات بياناتGET /api/projects
POSTأضف جديدPOST /api/admin/services
PUTعدّل/استبدلPUT /api/admin/services/:id
PATCHعدّل جزء صغيرPATCH /api/admin/messages/:id (مقروءة/مش مقروءة)
DELETEامسحDELETE /api/admin/services/:id

والرد بيرجع معاه رقم حالة (status code):

الكودمعناهإمتى بيحصل عندنا
200تمامقراءة أو تعديل ناجح
201اتعمل جديدإضافة ناجحة، رسالة Contact اتبعتت
204تمام ومفيش محتوىبعد الحذف
400الطلب غلطحقل ناقص، نص طويل، رابط مش http
401مش مسموحمن غير توكن، أو باسورد غلط
404مش موجودطلب CV ومفيش CV مرفوع
429طلبات كتيرتخطّي حد الـ rate limit
500مشكلة في السيرفرخطأ غير متوقع (بيتسجّل في الـ logs)

REST = طريقة منظمة لتسمية العناوين: كل "مورد" (resource) ليه عنوان (/services) والـ method بيحدد العملية. عشان كده كل موارد الأدمن نفس الشكل بالظبط (الفصل 9).

5رحلة الطلب في app.js

الـ middleware = دالة بيعدّي عليها الطلب قبل ما يوصل للراوت. في app.js الترتيب كده:

  1. app.set("trust proxy", 1) — Render فيه وسيط (proxy) قدام السيرفر؛ ده بيخلّي السيرفر يشوف IP الزائر الحقيقي.
  2. helmet() — يضيف headers أمان لكل رد.
  3. cors(...) — يسمح لموقعك بس إنه يكلم السيرفر من المتصفح.
  4. express.json() — يحوّل جسم الطلب (JSON) لـ req.body. (رفع الـ CV له حد أكبر: 6MB.)
  5. الراوترات — أول واحد عنوانه مطابق بيرد.
  6. معالج الأخطاء في الآخر — أي خطأ يتسجّل ويرجع { error } بكود مناسب (خطأ تحقق = 400).
server/src/routes/services.js — راوت كامل صغير 
router.get("/", async (req, res) => {
  res.json(await Service.find({ visible: true }).sort({ order: 1, createdAt: 1 }));
});

مفيش try/catch — express-async-errors بيبعت أي خطأ لمعالج الأخطاء لوحده.

6قاعدة البيانات (Mongoose)

MongoDB بتخزن مستندات (شبه كائنات JSON) جوه collections. Mongoose بيخلّينا نحدد شكل كل مستند بـ Schema، ونتعامل معاه بـ Model:

server/src/lib/mongo.js — مختصر 
const serviceSchema = new mongoose.Schema({
  titleEn: { type: String, default: "", maxlength: 120 },
  titleAr: { type: String, default: "", maxlength: 120 },
  icon:    { type: String, enum: SERVICE_ICONS, default: "web" },
  visible: { type: Boolean, default: true },
  order:   { type: Number, default: 0 },
}, { timestamps: true });            // createdAt / updatedAt لوحدهم

const Service = mongoose.model("Service", serviceSchema);
await Service.find();  Service.create({...});  Service.findByIdAndDelete(id);

قواعد في كل الموديلات

  • نسختين لكل نص ظاهر: ...En و ...Ar.
  • التحقق جوه الـ Schema (maxlength, enum, validate) — والتعديلات بتستخدم runValidators: true عشان تتحقق هي كمان.
  • _id بيتحول لـ id قبل الإرسال (transform في آخر mongo.js).

7تسجيل الدخول (JWT)

  1. الداشبورد يبعت POST /api/auth/login بالإيميل والباسورد.
  2. routes/auth.js يدوّر على الأدمن بالإيميل، ويقارن الباسورد بالنسخة المشفّرة بـ bcrypt.compare.
  3. لو صح: يعمل توكن JWT موقّع بـ JWT_SECRET وصالح 7 أيام، ويرجّعه.
  4. الداشبورد يبعت التوكن مع كل طلب: Authorization: Bearer <token>.
  5. middleware/auth.js (requireAuth) يتأكد من التوقيع. ولإن admin.js فيه router.use(requireAuth) في أوله، ولا راوت أدمن يتوصل له من غير توكن سليم.
ليه الباسورد مش متخزن؟بيتخزن hash بس (نتيجة تشفير باتجاه واحد). حتى لو حد شاف قاعدة البيانات، ما يقدرش يعرف الباسورد منه.
ليه نفس رسالة الخطأ؟لو الإيميل غلط أو الباسورد غلط، الرد واحد: "Invalid credentials" — عشان ما نقولش لحد مين الإيميلات اللي موجودة.

10الإيميل وإبقاء السيرفر صاحي

إيميلات الإشعار (lib/mailer.js)

لما حد يبعت رسالة، السيرفر يرد على الزائر الأول وبعدين يبعت الإيميل في الخلفية — فلو الإيميل اتأخر أو فشل، الزائر ما يستناش والرسالة متخزنة في الداشبورد على أي حال.

حالة الإيميل حاليًاخطة Render المجانية بتقفل بورتات SMTP، فالإشعار ما بيوصلش من السيرفر المنشور. الحل جاهز (خدمة Resend عبر HTTP) على branch اسمه feat/email-resend، ومؤجّل بقرارك. الرسايل والآراء بتوصل في الداشبورد عادي.

Keep-alive (lib/keepAlive.js)

Render المجاني بينيّم السيرفر بعد 15 دقيقة من غير زيارات، وأول زيارة بعدها تستنى حوالي دقيقة. الحل: السيرفر يزور /api/health بتاعه هو كل 10 دقايق، فما يوصلش لـ 15 دقيقة أبدًا.

  • بيشتغل على Render بس (بيعرف عنوانه من RENDER_EXTERNAL_URL)، ومش بيشتغل على جهازك.
  • للإيقاف: متغير KEEP_ALIVE=off على Render.
  • سيرفر صاحي طول الشهر بياخد ~744 ساعة من 750 ساعة مجانية.

11النشر على Render و Atlas

Render (السيرفر)

  • Web Service مربوط بالريبو، Root Directory = server، Build = npm install، Start = npm start.
  • أي push على main = Render يبني وينشر لوحده (2–3 دقايق).
  • الإعدادات السرية في Environment (مش في git أبدًا).
  • لو حاجة باظت: Logs فيها كل console.log و console.error.

MongoDB Atlas (قاعدة البيانات)

  • Cluster مجاني M0، ومستخدم قاعدة بيانات بباسورد.
  • Network Access لازم فيه 0.0.0.0/0 — لأن عنوان Render بيتغير.
  • رابط الاتصال: mongodb+srv://USER:PASSWORD@cluster0.xxxx.mongodb.net/salem_portfolio — اسم القاعدة قبل ?.
مؤجّل بقراركباسورد Atlas و JWT_SECRET وباسورد الأدمن اتكتبوا في محادثة قبل كده. المفروض يتغيروا قبل أي إطلاق كبير (الخطوات في ROADMAP.md).

12إضافة مورد جديد

مثال: "الشهادات" (Certificates). الجزء الخاص بالسيرفر:

  1. Schema + Model في lib/mongo.js وضيفه في models: 
    const certificateSchema = new mongoose.Schema({
  titleEn: { type: String, default: "", maxlength: 160 },
  titleAr: { type: String, default: "", maxlength: 160 },
  issuer:  { type: String, default: "", maxlength: 120 },
  url:     { type: String, default: "", maxlength: 300 },
  order:   { type: Number, default: 0 },
}, { timestamps: true });
  2. راوت عام routes/certificates.js (انسخ services.js) + سطرين في app.js (require و app.use("/api/certificates", ...)).
  3. راوتس الأدمن في admin.js (انسخ قسم Services): قايمة حقول مسموحة + GET/POST/PUT/DELETE.
  4. جرّب بـ curl أو من الداشبورد على جهازك، وتأكد إن البيانات الغلط بترجع 400.
  5. بعدها الجزء الخاص بالواجهة (موجود في دليل الفرونت إند، الفصل 10).

Schema / Modelشكل المستند وقواعده / الأداة اللي بتقرا وتكتب بيها.
Collectionمجموعة مستندات من نوع واحد (زي جدول).
JWTتوكن موقّع بيثبت إنك الأدمن.
Hash (bcrypt)تشفير باتجاه واحد للباسورد.
Rate limitحد لعدد الطلبات من نفس الجهاز في فترة.
CORSقاعدة في المتصفح: مين مسموح له يطلب من السيرفر.
Environment variableإعداد خارج الكود (أسرار، عناوين).
Deployنشر نسخة جديدة على السيرفر الحقيقي.
Proxyوسيط بين الزائر والسيرفر.
Cold startصحيان السيرفر بعد ما نام.
